## Retained limitations

The remediation diff does not change these implementation-backed limitations:

- Managed sensor runtime `config` is persisted but not injected into the child process or reliably retrievable through the normal sensor token path.
- Sensor `worker_affinity.preferred` is stored and validated but does not score placement.
- Author-facing trigger/sensor metadata fields documented in the sensor skill remain ignored by persistence where noted.
- Structured action output parsing remains best-effort; malformed JSON/YAML/JSONL does not necessarily fail a zero-exit process.
- `core.run_agent_command.command` still executes through `/bin/sh -c` and must be treated as worker shell access.
- `runtime_deps` remains persisted metadata rather than an install-preflight runtime guarantee.
- Removed standalone workflow definitions can still require explicit cleanup.
- Python distribution/import names (`attune-sdk` / `attune`) and JavaScript package/export names (`attune-sdk`, `attune-sdk/api_client`) are source-verified. Python sdist/wheel builds and JavaScript package smoke/freshness checks pass; the JavaScript dependency audit reports 0 vulnerabilities. API-environment E2E behavior remains a separate unrun gate.
- The recorded Java SDK notifier WebSocket lifecycle remains unsupported for the canonical managed sensor lifecycle, and its incompatible legacy RabbitMQ consumer is disabled; this does not limit its remediated numeric rule targeting.
